# 接口与数据说明

应用的 OpenAPI 文档位于启动服务后的 `/docs`。接口默认返回 `{"status":"success","data":...}`；业务错误返回 `status / code / message`，参数错误附带不包含输入值的 `errors`。

## 身份与请求规则

注册/登录成功后设置24小时有效的 HttpOnly、SameSite=Strict Cookie。数据库只保存随机 Cookie 的 SHA-256 摘要，可撤销；密码使用独立随机盐和 scrypt。

登录响应及 `GET /api/auth/me` 返回当前登录的 `csrf_token`，除登录/注册外的写请求必须带 `X-CSRF-Token`。前端只把 CSRF 令牌保存在内存，不把登录 Cookie 或密码写入 localStorage。

写请求体最多64KiB；认证接口每来源地址每分钟12次，咨询接口每用户每分钟20次，新建方案每用户每分钟30次。限流数据保存在 SQLite，重启保留当前窗口。默认不信任客户端自报的转发地址；反向代理后的来源识别需要单独配置。

## 接口清单

| 方法 | 路径 | 功能 |
|---|---|---|
| GET | `/api/health` | 版本、模式和应用存储探活 |
| GET | `/api/config` | 模式、示例线路与报价有效期 |
| POST | `/api/auth/register` | 邮箱、密码、昵称注册 |
| POST | `/api/auth/login` | 登录并建立 Cookie 会话 |
| GET | `/api/auth/me` | 当前用户和 CSRF 令牌 |
| POST | `/api/auth/logout` | 撤销当前登录 |
| GET/POST | `/api/conversations` | 查看/新建当前用户会话 |
| GET | `/api/conversations/{id}/messages` | 当前会话最近200条消息 |
| POST | `/api/chat` | 提交 conversation_id 和 message |
| POST | `/api/chat/stream` | 先完成并持久化请求，再以 SSE 发送整条结果；不是逐 token 流式生成 |
| GET | `/api/memory?conversation_id=...` | 读取当前会话上下文 |
| POST | `/api/memory/clear` | 只清空指定会话的消息与记忆；保留历史运行记录 |
| POST | `/api/memory/profile` | 保存指定会话的偏好字典 |
| GET | `/api/runs?conversation_id=...` | 指定会话最近100次运行 |
| GET | `/api/runs/{id}` | 读取属于自己的历史 Trace |
| GET | `/api/health/dependencies` | 登录后查看依赖探活；演示模式无外部依赖 |
| GET/POST | `/api/plans` | 当前用户方案列表/新建报价 |
| GET/PUT | `/api/plans/{id}` | 查看/编辑方案；编辑带 version |
| GET | `/api/plans/{id}/export` | 下载 Markdown 行程 |
| GET/POST | `/api/orders` | 当前用户订单列表/确认创建订单 |
| GET | `/api/orders/{id}` | 查看订单快照及状态 |
| POST | `/api/orders/{id}/pay` | 带 confirmed=true 模拟支付 |
| POST | `/api/orders/{id}/cancel` | 带 confirmed=true 取消或模拟退款 |
| GET | `/api/audit` | 当前用户最近100条活动 |

除探活、公开配置、注册和登录外均需登录。对象接口始终按当前用户归属查询，越权及不存在统一返回404。

## 方案请求示例

```json
{
  "origin": "北京",
  "destination": "成都",
  "departure_date": "请使用今天至未来180天内的YYYY-MM-DD日期",
  "days": 3,
  "travelers": 1,
  "budget_cents": 300000,
  "transport": "train",
  "include_insurance": true,
  "notes": "个人备注，不参与自动计算"
}
```

日期不是固定节假日样本。住宿日期按出发日至返程前一天拆分，每间房最多2人。交通包含去程和回程。预算检查采用：订单预订金额 + 餐饮及市内交通预估。门票不在当前订单中。

## 下单与错误处理

```text
POST /api/orders
Idempotency-Key: 客户端生成并在重试时保持不变的UUID
X-CSRF-Token: 当前登录对应的令牌

{"plan_id":"plan_...","version":1,"confirmed":true}
```

客户端不能提交订单金额。重试相同方案和版本会返回同一个订单；同一个请求编号换成其他方案返回409。

| 错误码 | 含义与处理 |
|---|---|
| authentication_required | 重新登录 |
| csrf_failed | 刷新页面获取当前登录令牌 |
| budget_exceeded | 调整人数、天数、交通或预算 |
| stale_plan | 重新读取当前方案并核对新报价 |
| quote_expired | 编辑/更新方案取得新报价 |
| price_changed | 目录价格变化，需要重新报价 |
| sold_out | 修改日期或方案；失败事务不会保留部分库存占用 |
| idempotency_conflict | 请求编号与方案不匹配，不应盲目重试 |
| plan_booked | 该方案已经生成订单，新预订请新建方案 |
| invalid_order_state | 根据订单当前状态重新选择操作 |
| conversation_busy | 同一会话正在处理上一条请求 |
| agent_unavailable | 联网模型或专家失败，查看历史运行和服务日志 |
| rate_limited | 稍后重试，HTTP 带 Retry-After |

## 数据表

应用表在 `product/store.py` 中定义，首次启动自动创建，`schema_version=1` 表示当前结构版本。`CREATE TABLE IF NOT EXISTS` 只用于新库初始化，不是自动结构迁移框架；后续修改字段需要显式迁移。

| 表 | 保存内容 |
|---|---|
| users / auth_sessions | 账号、加盐密码哈希、登录令牌摘要、CSRF 与过期时间 |
| conversations / messages | 用户会话、上下文、会话租约、历史消息 |
| runs | 用户/会话归属、状态、模式、Trace、耗时 |
| plans | 输入、版本、报价快照、有效期 |
| inventory | 产品+日期唯一、非负可用数量 |
| orders | 方案唯一约束、金额快照、状态、支付期限 |
| idempotency | 用户+请求编号唯一、请求指纹及对应订单 |
| audit_events | 当前账号的业务操作记录 |
| rate_limits | 固定时间窗口的限流计数 |

应用数据库与旧 MySQL 演示库不会混用。活动记录具有应用层可追踪性，不是防篡改审计系统。
