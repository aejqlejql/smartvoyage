# 运行与维护

## 配置优先级

系统环境变量优先，其次是项目 `.env`，最后是代码默认值。`config.example.env` 是无密钥模板；已有 `.env` 时不要覆盖。

| 变量 | 默认/用途 |
|---|---|
| SMARTVOYAGE_MODE | demo；live 调用原有 Agent 服务 |
| SMARTVOYAGE_API_HOST | 127.0.0.1，本地监听 |
| SMARTVOYAGE_API_PORT | 8080 |
| SMARTVOYAGE_APP_DB | 项目内 data/smartvoyage.sqlite3，可设置独立绝对路径 |
| SMARTVOYAGE_COOKIE_SECURE | 0；HTTPS 部署时设为1 |
| DASHSCOPE_API_KEY / OPENAI_API_KEY | 联网模型访问，默认模式不需要 |
| LLM_BASE_URL / LLM_MODEL_NAME | 模型兼容接口与名称 |
| SMARTVOYAGE_DB_* | 仅原有联网工具使用的 MySQL 演示库 |
| WEATHER/TICKET/TRIP_A2A_URL | 主服务访问专家的地址 |
| WEATHER/TICKET/TRIP_MCP_URL | 专家访问工具的地址 |
| SMARTVOYAGE_WEATHER_SOURCE | db 或 api；api 模式需配置天气服务 |
| MILVUS_HOST / MILVUS_PORT | 可选旅游团检索 |

双击启动器始终显式进入 `demo`，不会因为已有模型密钥而产生模型调用。联网模式请使用 README 中的手动启动流程。

## 日常检查

- `/api/health` 确认版本、模式与应用存储。
- 浏览器「活动记录」查看自己最近的业务操作。
- 「旅行助手」的历史运行记录区分 demo / live、成功/失败及耗时。
- 联网模式下 `/api/health/dependencies` 检查外部组件；TCP探活不等于某次业务查询一定成功。
- API 访问日志包含请求编号、方法、路径、状态和耗时，不记录密码、请求体或 Cookie。

原有 Agent 日志仍沿用 `logs/`；不要对外分享包含原始提示词、用户输入或供应商错误详情的运行日志。

## 数据备份与恢复

运行 `python -m ai01_SmartVoyage.scripts.backup_data` 使用 SQLite 在线备份 API，备份写入数据库旁的 `backups/`。不要在服务运行时仅复制主 `.sqlite3` 文件而忽略 WAL。

恢复步骤：

1. 停止本项目 API，确认没有本项目进程占用该数据库。
2. 保留当前库及相关 WAL/SHM 文件，作为恢复前副本。
3. 将备份复制到一个新的私密目录，设置 `SMARTVOYAGE_APP_DB` 指向该文件，避免覆盖当前库。
4. 重启后登录原账号，核对方案、订单和审计记录。

备份包含登录会话摘要及用户数据，应按私密数据保存。它与可分享的源码压缩包不同。

## 常见问题

**端口占用**：启动器会提示。设置另一个 `SMARTVOYAGE_API_PORT` 再运行，不需要结束其他项目。

**登录后写操作返回403**：刷新页面重新取得当前登录的 CSRF 令牌；多标签页发生重新登录时，旧标签页可能持有旧令牌。

**订单超时或退款后不能再支付**：这是状态机限制。新预订请新建方案，不能修改已经关联订单的报价。

**保存方案显示超预算**：程序计算包括往返交通、全部住宿及本地开销估算。不要仅比较交通单价和预算。

**聊天显示规则演示**：默认行为，没有大模型请求。设置 live 并启动依赖后才能验证联网链路。

**联网聊天失败**：确认模型配置与额度、专家及工具进程、MySQL 测试数据和日期是否匹配。当前演示方案的未来日期不保证旧 MySQL 样本具有对应记录；无数据应返回无数据，不能编造实时票价。

**测试目录权限错误**：使用 `scripts.verify`，它创建独立项目临时目录，不依赖机器的系统 Temp 权限。

**未安装完整模型依赖**：轻量演示只安装 requirements-demo。产品测试可使用 `scripts.verify --product-only`；运行原有 Agent 测试需 requirements.txt。

## 部署边界

SQLite 用于单机，不支持多个主机各持有一份数据库后仍声称库存一致。跨主机前应迁移数据库、限流和会话互斥机制。

后台每30秒处理过期库存。服务暂停时不会运行定时器，恢复后会补处理；所有下单、支付、订单读取也会先处理过期占用。

异步 HTTP 等待超时不能强行终止已经运行的 Python 工作线程。联网超时后，线程可能继续完成剩余外部调用，但实例是请求私有的，不会迟到写回会话，也不能通过聊天工具创建订单。每个 API 进程最多容纳4个联网工作任务，超时任务在线程真正结束前继续占用名额，防止请求超时后无限堆积后台线程。生产部署仍需要跨进程任务治理与工作进程管理。

本次不涉及公开发布。公开部署还应完成 HTTPS、Secure Cookie、账户验证/恢复、依赖锁定与扫描、真实供应商与支付对账等建设。
